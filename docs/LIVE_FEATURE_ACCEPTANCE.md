# 模拟器实际功能验收

日期：2026-10-29。环境：用户现有MuMu模拟器，Android15/API35，竖屏900×1600、桌面横屏1600×900。

正式App当时是另一个工作区正在开发的0.4.9.3/code16，尚未包含完整养成主线。为保留其五子棋记录、聊天、配置与Key，本轮使用同一模拟器中的独立验收包：com.dafeiyu.featurechecks（新用户）、com.dafeiyu.growthchecks（合成旧用户），以及com.dafeiyu.compatchecks运行时检查包。它们复用产品UI、资源、服务与存储类；QA Application只隔离模型/网络与预置合成用户数据，不改产品UI交互实现。通过真实点按、截图、Android字体布局和服务日志核对，不以读取控件文本代替全部视觉检查。

## 发现并修复

1. 主分支漏带此前已验收的自然短气泡：移入已有ReplySegments实现，新轮次保存segmentVersion，旧记录按原边界解释可见计数，界面只重排已显示内容。实际同一句“会一点，不算大厨……”由长气泡变成3条。
2. 新用户确认人格后仍显示“今天还没见面”：确认成功后调用现有meet再刷新首页。实际新装后立即显示“已见面”，羁绊5、小鱼干5；重复进入不重复发奖。
3. 播放“悠闲哼歌”后约1秒被待播章节抢占：quietMoment补上角色busy判断，等待当前动画完成再进入章节，保留聊天优先和其他可见性判断。

## 验证

前两处修复后42项针对性Robolectric回归通过（聊天、成长、称呼、主动调度），Android17组核心通过（分段/历史605项、养成3620项、性格217项等），独立运行时57项通过。最后的动画等待修复重新构建后，17组Android核心再次通过；6项成长界面复验通过。实际PetService/视频解码回调检查通过：手动动作播放期间剧情不抢占，10497ms后收到动画完成回调，待播章节才开始。全部验收包已卸载，原正式App仍为0.4.9.3/code16。

## 边界

- 本轮没有覆盖安装或清空正式com.dafeiyu.companion；清空只针对自己创建的验收包合成数据。
- 老用户是明确的迁移样本，并非用户真实历史或自然游玩45天的证明；没有改系统时间，没有直接填主动调度计划。
- 真实模型五种人格辨识度、跨天自动日记/相处理解、完整1–4小时自然旅行等待、实体手机与长期耗电未验收。本次不能声称这些路径全部通过。
- 右侧偶尔可见另一只桌宠来自原正式App，非验收包重复创建。
- 测试APK不作为新版分发，不递增版本、不更新Release或国内镜像。截图仅保存在本次本地outputs，未放公开仓库。
