# 五子棋与对局记录

入口：首页“我们 → 一起下五子棋”；助手已经展示的消息中提到五子棋，会出现“开始对局 · 五子棋”。点击才打开游戏，不由模型自动开始或代用户落子。桌面气泡先进入聊天记录，再点对局按钮；旧的“下五子棋”小动作仍只是动画。

15×15棋盘，自由规则，用户执黑先手，大肥鱼执白，任意方向连续至少五子获胜，无禁手。落子分两步：第一次点交点只显示半透明预下棋子，同一点再点一次才落子，点别处换位置。棋盘支持触控与带坐标的无障碍控件（预下的点会读作“已预下，再点一次落子”）。

## 她的棋力

本机对手分五档，逐手计算都在手机上完成，下棋本身不消耗模型额度：

- 菜鸟：普通人水平。能赢一定赢，对方冲四大多会堵（约八分之一的时候漏看），在看起来不错的前五个点里随手挑。
- 中下：能赢就赢、该堵必堵，在前三个点里挑，好点更常选。
- 中等：每次下评估最好的点（五格窗口：同一方在任意连续五格里的子数越多分越高，进攻与防守相加，能看出跳活三）。
- 中上：中等的选点，加上找到就走的连续冲四杀，并避开会让对方连续冲四或活三取胜的点。
- 大师：更深的连续冲四和连续活三（VCT）杀棋搜索，防守同样检查两者；搜索都有工作量上限，手机上不会无限思考。

开局时档位为空。棋盘打开后，后台用一次非流式小请求（与聊天同一模型服务商）发送她的性格说明、当前心情（记忆关闭时不含起因）、用户最近几句话和对局记录，让她返回 `{"level","reason"}`；只接受五个已知档位，理由按心情起因的规则过滤。没接通模型、请求失败，或轮到她下时（已接通模型则最多等4秒）还没回答，就按性格、心情和最近三局胜负就地选（温柔偏菜鸟/中下，傲娇和元气偏中等/中上，冷静可靠偏中等到大师，古灵精怪五档都可能；她在担心用户或用户连输三局时降一档，用户连赢三局时升一档）。档位一旦确定就不再改，迟到的回答被忽略。

棋力只存进棋谱和对局资料，界面任何地方都不显示；对局记录弹窗也不显示。

收起保存当前局；重启可继续，未完成的白方响应会补走。“结束本局”需确认，记为主动结束而不是输；“再来一局”开始新ID，未结束且已经落子的旧局需确认结束。未落子空棋盘被重新开局替换时不计一个结束结果。

## 存储

App私有目录agent/gomoku/current.json保存当前棋谱；results/<UUID>.json为每个结束棋局的独立文件，使用原子写入。完局先写结果再写当前状态，若中途退出，按同ID结果恢复；不会重复累计。没有固定结果淘汰上限，受设备空间限制。

schema=1；id稳定UUID；startedAt/finishedAt为Unix epoch毫秒；timeZone为开局时区，结束展示也使用该时区；level为rookie/lower/middle/upper/master，新局未定时为空字符串，旧版没有该字段的棋局按middle读取；levelReason为她选档时的心里话，levelBy为model、fallback或legacy；moves为按先后排序的0–224交点下标（下标=行×15+列，偶数手黑方，奇数手白方）；outcome为playing、user_win、pet_win、draw、abandoned。开始/结束时间均保存，不保存每一手的独立时间戳。

读取时重放棋谱校验轮次、范围、重复落子、终局后落子与胜负，不直接相信结果标签。损坏结果不计入已验证统计，界面提示不完整。结束记录含完整棋谱；当前没有分享/导出棋谱界面。

## 模型上下文与删除

记忆开启、非明确历史聊天查询时，runtime注入game_results：user_wins、pet_wins、draws、abandoned累计数，recent_results最近8局的ID、开始/结束时间、时区、可读结束时间、手数、结果、棋力level（未定为undecided）和level_reason，以及未完成局的手数/轮次/棋力。提示词说明棋力是她悄悄选的、用户看不到，可以自然流露让没让，不报等级名。它是应用实际操作产生的资料，不是用户发言；不能把主动结束算输，不能根据角色“经常输”的设定虚构战绩。

完整历史文件为以后检索保留，目前模型不会按任意日期扫描全部棋谱。关闭“记住重要的事”不注入专门战绩背景；已有聊天中的比分仍是普通聊天记录的一部分。

棋局独立于对话与用户事实记忆。普通清空聊天保留棋局；“忘记全部对话和记忆”的确认提示包含棋局与战绩，并一起删除。已清空的旧局ID不能被迟到回调继续写回。完成棋局不再额外写一条普通触摸事件，避免重复保存结果来源。卸载或清除App数据也会清除本机棋局。

真实棋盘是独立可用入口；章节解锁控制的“下五子棋”小动作仍是动画，两者不互相冒充。当前棋局战绩不自动增加亲密值或其他养成数值。
