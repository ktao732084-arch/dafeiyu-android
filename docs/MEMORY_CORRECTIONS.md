# 更正记忆与回复完整性

普通聊天的 `memories` 字段可能被模型省略，不能把“记住了”当成保存凭据。`MemoryCapture` 和 `NativeMemoryEngine.autoFacts` 从用户原话补充事实：区分“没怎么喝”这类陈述和提问，识别常买、常喝等习惯，以及明确的更正、改期。

更正和紧随其后的范围说明作为一条逐字来源保存，例如时间改期后“还是原来的地方”、饮品更正后“不加糖没变”。完整更正优先于模型给出的局部摘录，仍受每轮三条、敏感内容、问题句和代写素材过滤约束。后续去重、替代和归档继续由原有记忆引擎处理，不以模型回复作为用户事实。相关旧事实保留在历史中，通过 `superseded_by` 连接新事实。

复述请求和练习结束语不属于用户事实，即使模型给出逐字摘录也不接收。已有同类非手动记录也从普通召回中排除；手动固定的记录保留用户控制权。实际项目进展（如“我的项目代码已经写完了”）仍可保存。

`NativeMemoryTime` 支持没有“这/下”前缀的星期表达，按观察日期所在周换算。取消的日期仍留在来源与换算文本中，但不作为新安排的 `event_date` 或过期日期；“从周六改到周日”没有写“取消”时也优先采用替代日期。每周重复的安排不变成一次性事件。没有明确周次的表达仍有歧义，这不等同于通用时间理解器。

`ReplyIntegrity` 在保存前校验文字：

- HTTP JSON 和 SSE 使用严格 UTF-8 解码；非空损坏 SSE 数据不会被静默跳过。
- 检查替换字符和未配对代理字符，包括 JSON 转义后的正文、嘀咕及记忆字段。用户主动讨论替换字符时允许显示该字符。
- 聊天和桌宠回应发现损坏后，原请求最多重试一次；不把损坏回复加入请求。连续失败或取消不落盘。普通连接失败不因此重试。
- 流式预览过滤损坏片段；润色完成后还会校验最终文本。
- 历史、片段回忆、近期互动摘要、日记等进入模型时使用副本标记损坏文本，不改写原存储记录。

人格与采样参数保持原样。表达规则要求复述事实时直接说准确的结果，不靠插入无关词再改口制造口语感；这不能保证模型永远不产生病句。

模型把嘀咕写成正文末尾独立的 `<aside>…</aside>` 时，`AgentReply` 将它恢复到专用字段；流式正文隐藏这个尾部，关闭嘀咕时仍不显示它。用户明确请求标签、HTML、代码或原样输出，以及代码围栏内的内容，不作这种转换。

`CorrectionIntegrityTest` 覆盖真实复现句型、来源完整性、旧事实归档、日期、重开存储、编码、重试和上下文隔离。`CompanionBehaviorTest` 用本地 HTTP 服务验证损坏字节、损坏 SSE 和 JSON 转义替换字符；`AgentInstrumentation` 验证 Android 回调及保存边界。真实模型聊天与截图仅保存在本地测试目录。
