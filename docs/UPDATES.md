# 轻量更新实现与验证

开发分支 `codex/lightweight-updates` 基于 `f6203eb`，与记忆实验及其他工作区隔离。版本仍为 0.4.6 / code 10，没有发布新版本。通用构建默认配置为空；后续已按用户选择接入北京公网 IP + HTTPS，使用独立构建入口，见 [部署记录](../deploy/updates/BEIJING.md)。

## 实现范围

- 独立更新线程及偏好文件，不调用模型，不改写聊天或人格记忆。
- 启动与已有桌宠亮屏心跳触发每日最多一次检查；自动失败保持安静。手动检查绕过每日间隔及忽略版本设置，并展示失败原因。
- 新版本可查看、稍后处理、忽略；自动提醒同一版本每天最多一次。聊天、模型忙碌、人格初始化或更新页面打开时不叠加提醒。
- HTTPS 同源下载，限制重定向、大小、超时；进度、取消、临时文件清理和重试。没有断点续传或静默后台下载。
- 下载后及安装前核验文件大小、SHA-256、真实 APK 包名、版本、系统兼容和当前签名证书。损坏缓存被清除，可重新下载。
- APK 存在私有目录，只向系统安装器授予指定文件的临时只读权限。安装权限由用户到系统设置开启，返回后仍需点击安装及完成系统确认。
- 国内服务器只托管静态 JSON 与 APK。发布脚本从实际签名包生成清单，先落盘 APK，再原子替换清单，拒绝证书错误及重复/倒退版本。

## 验证记录（2026-10-29）

- 产品构建通过，开发测试密钥的 APK v2/v3 签名验证通过；没有使用或交付测试包作为正式升级包。
- `UpdateCoreTest`：26 项通过，覆盖解析、版本比较、限频、HTTPS/跳转约束、流式下载、缓存、取消、截断、超量和哈希错误。
- `tests/test_update_publish.py`：6 项通过；另用实际构建 APK 调用 aapt/apksigner 完成生成站点目录的本地联调。
- Robolectric 首轮全套 84 项通过，含既有聊天、界面、记忆与 8 项更新测试。补充安装权限返回、损坏缓存重下载后，在最终产品类上复跑 UpdateTest、UiTest、ConversationTest，共 33 项通过（10 项更新、14 项界面、9 项聊天），无失败或跳过。
- Android 14 / API 34 模拟器 ART：12 套核心检查通过，其中更新检查为同一套 26 项；既有 84 场景记忆基线保持 145/166，原有未满足项没有被更新功能修复或隐去。
- 独立 `com.dafeiyu.updatechecks` 测试包：最终构建的 30 项检查通过，包括实际 PackageManager 解析同签名后续版本 APK、安装参数、私有 Provider 读取与拒绝写入、损坏文件拒绝，以及既有受控模型 Runtime 检查。正式包 `com.dafeiyu.companion` 和其他工作区的测试包未被覆盖或清空。
- 检查最终 DEX 中新增平台 API：API 28 的版本号和签名接口均有 SDK 判断；安装授权接口为最低支持的 API 26。

以上首轮测试网络为受控连接或本地 HTTP 记忆服务，没有请求真实更新域名或真实模型。后续北京公网 IP、TLS 与下载联调记录见 [北京更新入口](../deploy/updates/BEIJING.md)。未跑实体手机，未执行正式旧版本到新版本的系统覆盖安装，厂商安装器体验仍需发布前验证。

## 后续发布

通过 `deploy/updates/build-beijing.ps1` 或 `build.ps1 -UpdateUrl` 配置，并用原正式证书签名、递增版本号。已有旧版用户需要先手动覆盖安装一次支持更新且带真实地址的新正式版。不要卸载旧版；正常同包名、同签名覆盖安装保留私有数据。发布前应先合入最新发布分支，避免覆盖其他并行修复；本分支不自动合并其他工作区。
