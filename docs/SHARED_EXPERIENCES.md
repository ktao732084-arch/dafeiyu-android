# 共同经历与她的回想

基于主分支 `805ea9d`（0.4.9.4）和人格分支 `1c6a86b`。复用已有日记、相处理解、聊天档案和真实棋谱，不新增记忆服务、向量库、OCC 或定时器。人格分支负责“她是谁、现在怎样说话”；这里负责“发生过什么、后来如何回想、怎样找回来和删除”。

## 整理流程与预算

打开应用或完成聊天后，本地检查能否整理。开启记忆和陪伴日记、已初始化人格、已配置模型、聊天空闲时，后台检查最近三个已结束的本地日期。至少有三条可用用户聊天，或者一场实际完成的五子棋，才可以请求模型；仅有摸头、喂食等互动不触发整理。

- 每个本地日期最多请求一次，发请求前持久化尝试日期。失败当天也不重试；没有合适材料不消耗次数。
- 聊天读取完整档案的当天记录，取有界的近期摘录，不依赖最近 160 轮缓存。每条用户原话最多 150 字、实际展示回复最多 80 字，沿用约 6000 字符的聊天素材预算。
- 棋局读取当天持久化棋谱，不受聊天背景最近 8 局的限制。只使用实际胜负或平局，主动结束不算胜负。互动来自现有最近 200 条记录；已移出窗口的互动不承诺能补写。
- 最多提交 12 条事件，优先保留棋局再按时间排列。事实由程序生成，模型不能修改棋局胜负。
- 复用原来一次日记调用及人格分支的 `diaryGuidance`；共同经历阶段输出上限从 700 增至 950 tokens，随后因[双方约定](COMMITMENTS.md)补漏提高到 1300。没有额外分类或聊天前模型调用。
- 模型最多选一个已有 `source_id`，写 1–80 字的第一人称回想；没选片段时允许旧式日记输出。没有文字聊天的日期，必须返回有效来源片段，否则不保存。
- 相处理解仍由同一次请求处理，只接受实际提供的用户原话，不以游戏、互动或模型自己的感受为证据。

来源编号、字段类型、长度、敏感内容由代码检查；回想是否自然、有分寸仍取决于模型，代码不能证明每句感受的语义可靠性。

## 存储与检索

继续使用 `diary` 数组，每天最多一页、最多保留 400 页。新页沿用 `date/text/at/sources`：`text` 是她后来写的回想，`at` 是整理时间。附加的 `moment` 是程序从提交材料中复制的来源快照，包含种类、原始编号、发生时间、时区和事实；聊天片段额外带原话/实际展示回复的摘录，棋局带真实 outcome。

新整理的聊天片段可带 `moment.context`：选中句子之前最多两条、相距不超过 15 分钟、实际提交过的用户原话摘录，分别保留 turnId 和时间。用于保住上下文主题，不另造模型关键词、不写进用户事实。旧页不回填；缺字段时照旧可读。检索命中后以 `context_quotes` 带入，并明确它们是用户原话，不是她自己的经历；手账依据页也能查看。

不让模型自由写事实字段，也不把回想写进用户事实、她的自我陈述、当前心情或冻结人格。过去的回想不会把当下情绪重新计时。聊天引用明确区分“发生的事”和“后来写的回想”。

每轮聊天最多选两页：从所有保留页中找本轮相关内容，考虑事件事实、回想和有来源的上下文摘录；各段分别算相关度取最大值，避免新增上下文冲淡主事件。日常聊天没有匹配就不带日记，防止换话题后仍被旧片段拉回；只有无明确话题的空查询（如主动考虑）才取过去七天最新两页。沿用本机词面相关度，补充“下棋/棋局”到“五子棋”，以及论文、作文、写稿、文章、文档、动笔到“写作”的小组别名；不承诺任意同义表达、复杂跨事件推理或无限期保存。

整理时明确要求写现在对结果的态度，不重建当时的心理、动作或感官画面；没有值得写的感受可以不选片段。使用日记时才注入事实与回想边界；用户明确问“还记得吗”等旧事、且不是专门的历史搜索时，另带一次核对依据的说明：问题中的名字不是记忆，没有对应资料就坦然索要线索，不能猜，也不把没找到说成没发生。这些仍是生成约束，不是逐句语义证明，也不增加模型调用。

旧日记不重写、不推造证据；界面标为“旧日记”，说明旧格式没有逐条依据快照。新模型若返回兼容旧格式，也按无逐条快照的日记展示。

## 手账与删除

手账保留唯一入口，分为“关于你的记忆”“我们的经历”“历史与整理记录”等原有分组，不与“我们的故事”互相链接。

“我们的经历”支持按文字/日期搜索、每次显示 20 页、查看依据和单篇删除。依据页区分发生时间与整理时间，聊天明确标注为摘录。单篇删除确认后保留原聊天、棋局和用户事实，只删除小记及快照，并保留日期标记，防止自动补写。

- 删除来源聊天：选中主片段的 `sources` 被删时删除小记；若删的是 `moment.context` 的来源，只移除对应上下文摘录，主片段保留。保存时也核对上下文来源的删除标记，防止迟到结果带回已删内容。
- 清空共同经历：记录清空时间，清空前的聊天、棋局、互动不能再用于补写；原始聊天和棋谱仍可在各自页面查看。
- 清空聊天：同时清空小记、相处理解和互动，并设置补写截止点。棋谱继续按既有产品规则保留；全部忘记才连同棋谱清除。
- 删除和清空都会更新 epoch、清除备份，生成中的迟到结果不能恢复被删除内容；提交棋局片段前再次核实棋谱，提交互动片段前核实来源仍存在。
- 单独删除小记不删除同次调用产生的相处理解；它仍有独立的用户原话证据和删除入口。

导出按钮改为“导出手账（含近期对话）”。导出包含现有手账、来源摘录、近期聊天和养成快照，明确不包含完整聊天档案、完整棋谱回放或 API Key。

## 验证与边界

`DiaryTest` 检查真实棋谱来源、超过最近 8 局、旧经历检索、格式拒绝、时区、未展示回复、来源删除、单篇删除、清空截止点及导出往返。`SharedExperienceUiTest` 检查入口触发、每天一次、开关、整理中清空、分页搜索和删除回调。

`ExperienceInstrumentation` 在独立包中使用合成历史和受控模型，运行实际 Android 主界面、后台调用、依据页与删除流程，并截图检查文字布局。未改设备时间，未使用正式应用数据。测试证明存取、检索、隔离与界面流程；不证明真实模型的情绪价值或长期陪伴质量。最终结果见 `docs/test-reports/shared-experiences.json`。

随后用真实 `deepseek-flash` 跑了两种风格、各两次的试聊及对照。来源存储正常，但旧经历的换说法检索、回想中的未记录细节、无记忆时仍声称记得等效果问题尚未通过验收；当前不建议据功能测试通过就合并。汇总见 [真实模型试聊结果](test-reports/shared-experiences-live.json)。可选入口为 `tests/com/xiaoxiao/pet/SharedExperienceLiveEval.java`，不进入默认测试；使用环境变量或隐藏输入接收 Key。完整报告和回复只留在忽略目录 `build/live-experience-checks/`。

针对上述结果，本次只增加有来源的短上下文、少量检索别名和条件化生成约束；没有改固定人格或记忆引擎。优化前后及中间失败样本的汇总见 [检索与回想优化复测](test-reports/shared-experiences-refinement.json)。
