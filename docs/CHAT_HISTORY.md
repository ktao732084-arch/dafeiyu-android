# 聊天记录与检索格式

0.4.4开始使用。时间统一为Unix epoch毫秒（UTC绝对时间），不依赖格式化日期字符串检索。

| 字段 | 含义 |
|---|---|
| id | 一轮对话稳定ID，翻页、归档、重启不变 |
| at / receivedAt | 点击发送时间；主动消息为本轮发起时间 |
| repliedAt | 最终回复完成并提交记录的时间 |
| timeZone / utcOffsetMinutes | 记录时IANA时区及发送时刻的UTC偏移 |
| displayed | 已展示完整段数；旧记录无此字段，按旧版完整回复处理 |
| segmentVersion | 保存该轮时的分段算法版本；缺失按v1，v2边界冻结，v3增加省略号/破折号与较短逗号分句 |
| displayedAt / lastDisplayedAt | 首次与最近一段展示时间；未展示时不存在 |
| segmentDisplayedAt | 按段顺序记录首次展示时间；打开全文时补记当次时间 |
| displayTimeZone | 最近一次展示时区 |
| user / reply / proactive | 用户原文、完整最终回复、是否主动消息 |
| interaction | 物理互动回应的动作证据；后续源码中聊天UI按此标记隐藏该轮，记录与模型上下文保留 |
| pageKey | 分页游标，不代替业务ID |

工作状态companion-v1.json仍保留最多160轮及4MiB边界。移出窗口的已提交对话原子写入私有chat-history目录。当前窗口与归档合并去重，按发送时间与稳定ID排序；读取上限40轮，界面每页20轮。

historyRange(fromInclusive, toExclusive, beforeCursor, limit)使用半开区间[开始毫秒,结束毫秒)，对近期和归档统一检索。界面把所选本地日期的当天与次日起点按时区规则转换区间，包含夏令时变化。显示用记录时区，改变设备时区不改写旧时间。

旧记录保留原有at，缺失的完成/展示时间和时区不伪造。界面对旧记录以原时间和当前时区回退显示。旧版已经淘汰的记录无法恢复。

归档在近期状态淘汰旧轮次前完成；归档失败则停止保存本轮，避免静默丢失历史。完整归档不进入模型请求，近期上下文与原生记忆仍有限额。

忘记直接来源或清空聊天时先写不含正文的删除标记，再清理归档和近期记录，旧主文件备份无法让被删轮次回流。离开气泡不会删除记录。用户自行备份/导出和服务商端数据不在本机删除范围内。

展示进度每段出现时先在内存里更新，随后由后台线程写入文件（多段合并为一次写入）；完整保存仍是同步的，并会带上已有的展示进度。若写入前进程被结束，最多少记最近一两段已展示，不会把未展示内容记成已展示。归档目录在首次使用时列出一次，之后随写入和删除同步更新。

历史保留受设备存储空间限制，无云同步。手账导出暂不包含全部历史文件。展示时间表示内容曾呈现或全文已打开，不等于用户已经阅读理解。

0.4.7起，助手旧记录的前导`[tool]`/`[assistant]`通道标记在界面与可见上下文中隐藏，原始`reply`及时间戳不改写。新回复在解析时移除这些前导标记后保存。分段仍根据该轮保存的完整文本计算，未展示部分仍不能冒充已展示；修复了未展示按钮导致首段截字的问题。称呼同步与历史回顾互不混用，规则见[NICKNAME_SYNC.md](NICKNAME_SYNC.md)。

## 分段版本与旧消息

后续分段修复采用v3：短句保留，较长句子按自然标点与停顿无损拆分，不按屏幕宽度合成大气泡，不调用额外模型。较长逗号分句的目标从28字降到22字，保留最小前后语块；引号、括号、数字中的分隔符以及代码/链接继续保护。并非强制每段等长，没有合适标点时不从字中间截断。

旧v1/v2的`displayed`仍按原算法解释，只对已展示前缀在聊天页重新排成短气泡；不改原文、展示计数或时间，不暴露未展示内容。新生成的聊天和桌面气泡均用v3及原有顺序播放队列。

## 0.4.5 回复阶段自动使用历史

HistoryRecall.plan识别明确的时间回顾请求；普通无时间的记忆提问仍走原路径。AgentRuntime在模型调用前通过AgentStore.recallHistory查询ChatArchive，再将historical_chat_search放入最后一条用户消息的背景数据。

返回包含from_inclusive、to_exclusive、query_zone、range、matched_turns、scanned_turns、selected_turns、scan_complete、partial、topic_match及records。每条摘录带稳定ID、发送时间、完成/展示时间（若原记录存在）、原时区、用户原话和助手已展示部分。旧版无展示字段的助手文本单独标记为assistant_saved_excerpt及legacy_unknown；新记录未展示部分不提供。

每次扫描最多1000轮和8MiB正文；超限时均匀取样并标记不完整。每次最多24条、约14000字符证据，概览优先覆盖不同日期。字段partial表示扫描、筛选或原文摘录可能不完整，回答不能冒充全量总结。时间以每轮用户发送时间为范围依据，主动消息按发起时间；助手时间另外保留。

明确查询自己的历史不依赖自动记忆开关，也不触发额外智能记忆请求或将旧话重新写入事实。无记录/日期不清/读取失败直接给出相应说明；有记录且已配置模型时由当前模型归纳，没配置时仅给原文摘录。已删除标记始终有效，取消不降级为捏造结果。

这不是任意自然语言都能识别的通用时间解析器。支持本版列出的中文时段与数字日期；不明确的请求需要补充具体范围。没有声称能恢复旧版淘汰数据，或能在一次有限上下文请求里完整概括任意数量的历史。

## 0.4.8 物理互动与主动决定

完整聊天与近期物理互动分开保存：点击/拖动等interactions只保留最近200条，包含epoch毫秒与时区；主动决定initiativeChecks保留最近100条。它们不替代完整聊天归档，安静决定不伪造聊天轮次。主动生成且提交的消息仍按相同聊天字段记录，未展示状态仍有效。清空聊天一并清理这些近期事件和计划；详见[主动陪伴](PROACTIVE_COMPANION.md)。

0.4.9.1新增每轮`initiativePlan`调度元数据（来源、合法分钟数、忙闲依据、主题与是否补齐），保存成功的正文与时间戳不受补齐失败影响。等待或真正安静不新增伪聊天轮次；清空聊天一并删除等待状态及计划。见[主动陪伴](PROACTIVE_COMPANION.md)。

## 连着发几句

她回话时输入框不再锁住。

- 输入框为空时，按钮是「停止」，作用和以前一样。
- 输入框有字时，按钮是「发送」，表示补一句：
  - 她这条回复还没保存：这条回复会悄悄停下，不显示“已停止回复”。你发的几句用换行合成同一轮，一起交给她回答。实测模型本来就会把这几句当成一件事来回，所以没有在提示词里另加说明；场景测试 `double-text` 会盯着这一点。
  - 她的回复已经保存（只有一瞬间的窗口）：补的话回到输入框，不会打断她正在逐段显示的回复，避免这条回复被记成“没展示过”。
- 主动消息和触摸回应不会被补发的话合并。
