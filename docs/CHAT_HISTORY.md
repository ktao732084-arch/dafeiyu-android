# 聊天记录与检索格式

0.4.4开始使用。时间统一为Unix epoch毫秒（UTC绝对时间），不依赖格式化日期字符串检索。

| 字段 | 含义 |
|---|---|
| id | 一轮对话稳定ID，翻页、归档、重启不变 |
| at / receivedAt | 点击发送时间；主动消息为本轮发起时间 |
| repliedAt | 最终回复完成并提交记录的时间 |
| timeZone / utcOffsetMinutes | 记录时IANA时区及发送时刻的UTC偏移 |
| displayed | 已展示完整段数；旧记录无此字段，按旧版完整回复处理 |
| displayedAt / lastDisplayedAt | 首次与最近一段展示时间；未展示时不存在 |
| segmentDisplayedAt | 按段顺序记录首次展示时间；打开全文时补记当次时间 |
| displayTimeZone | 最近一次展示时区 |
| user / reply / proactive | 用户原文、完整最终回复、是否主动消息 |
| pageKey | 分页游标，不代替业务ID |

工作状态companion-v1.json仍保留最多160轮及4MiB边界。移出窗口的已提交对话原子写入私有chat-history目录。当前窗口与归档合并去重，按发送时间与稳定ID排序；读取上限40轮，界面每页20轮。

historyRange(fromInclusive, toExclusive, beforeCursor, limit)使用半开区间[开始毫秒,结束毫秒)，对近期和归档统一检索。界面把所选本地日期的当天与次日起点按时区规则转换区间，包含夏令时变化。显示用记录时区，改变设备时区不改写旧时间。

旧记录保留原有at，缺失的完成/展示时间和时区不伪造。界面对旧记录以原时间和当前时区回退显示。旧版已经淘汰的记录无法恢复。

归档在近期状态淘汰旧轮次前完成；归档失败则停止保存本轮，避免静默丢失历史。完整归档不进入模型请求，近期上下文与原生记忆仍有限额。

忘记直接来源或清空聊天时先写不含正文的删除标记，再清理归档和近期记录，旧主文件备份无法让被删轮次回流。离开气泡不会删除记录。用户自行备份/导出和服务商端数据不在本机删除范围内。

历史保留受设备存储空间限制，无云同步。手账导出暂不包含全部历史文件。展示时间表示内容曾呈现或全文已打开，不等于用户已经阅读理解。
