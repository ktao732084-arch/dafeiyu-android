# 她现在：角色状态层

目标：面对同一件事，大肥鱼会因为当时的状态和刚经历过的事，做出有原因的不同反应。这种变化要能延续，也要能自然结束。用户画像只是其中一部分，这一层关注的是她自己。

设计参考了白艾莉的公开方法论，以及对其 1.3.45 客户端的静态调研。借鉴的只是机制：稳定底稿、按条件装配、状态在回复之后更新、睡醒分阶段、重复提醒后收住。没有移植代码、提示词或角色文案。

## 原则

1. **能从应用状态知道的，不再问模型。** 是否刚被叫醒、刚喂过食、刚输了棋，都有可靠的本地记录。这些判断全部由程序完成，不增加模型调用。
2. **只来自真实记录。** 状态由互动记录、对局结果和聊天轮次推出，不编造经历或计划。遵守 AGENTS.md 中“不为她编造会持续推进的个人生活”的约定。
3. **每轮重算，不另存一份。** 状态是 `CharacterNow` 根据现有记录算出的纯函数结果，不新增存储。清空聊天或删除棋局后，相关状态自然消失，也不会残留需要单独清理的数据。
4. **结束要明确说出来。** 刚醒、刚经历的事、邀请这几类状态过去后，会先写一句“已经过去了”再停止注入。只是不再提起，模型可能会顺着聊天历史继续沿用旧状态。
5. **状态影响表达，不影响正事。** 用户认真求助或倾诉时，不再强调输棋、再来一局之类的话题。

## 本轮注入的“她现在”

背景中的心情之后，最多加入一段五行以内的“你现在”。只写本轮适用的行，没有就整段不写。

| 行 | 来源 | 规则 |
|---|---|---|
| 睡醒 | `kind=wake` 的互动记录 | 被叫醒后她还没开口，写“刚被叫醒，还有点迷糊”；已经回过话、且距叫醒不到60分钟，写“醒来约N分钟，已经清醒，刚被叫醒的事过去了，不再提” |
| 刚经历的事 | 30分钟内的喂食、剧情记录，以及60分钟内结束的对局 | 最多3件，带“N分钟前”。如果她之后已经回过话，标注“已经回应过，接着聊时不必重演第一次的反应” |
| 短期意图 | 见下节 | 同一时间最多一个 |
| 已经说过的提醒 | 她最近3条回复 | 提醒过睡觉、吃饭、喝水或休息，而用户本轮没有再提这个话题时，加一句“刚提醒过，这次接着对方的话聊，不再重复” |

叫醒记录改为使用独立的 `wake` 类型，包括消息叫醒和戳醒；剧情使用 `story` 类型；其他互动类型不变。这一段只注入普通聊天、主动考虑和触摸回应。回顾历史时不注入。

## 短期意图：输棋后想再来一局

第一版只做一种意图，生命周期也全部由本机记录推出：

```text
产生：最近一局是 user_win（她输了），结束不到120分钟，且之后没开新局
  └─ 待邀请：可以在合适时邀请再来一局，不要硬插
       ├─ 她回复中提到五子棋或再来一局 → 已邀请：等对方决定，不再重复邀请
       │     └─ 用户随后表示不想下、改天、在忙 → 已放下：这事放下了，不再邀请
       ├─ 开了新局 → 结束（不再注入）
       └─ 那局结束超过120分钟 → 结束
本轮用户在倾诉或求建议（沿用 Understanding.scene）→ 这一轮先放一边，不提
用户说过在忙、应用正在等待 → 不注入
```

“已邀请”和“对方拒绝”直接复用 `GomokuInvite`，与聊天页是否显示「开始对局」按钮用同一套规则：只提到五子棋、报战绩或引用旧邀请都不算邀请。这一判断不让模型额外输出字段。

## 示例暂不按场景拆分

曾考虑把示例按场景拆开，只在相同场景时注入。实际分类后，15句里只有“被领导骂了”一句会被现有关键词识别为特定场景；其余如被夸、求助公式、好消息都识别不到。若靠扩写关键词把更多示例移出系统消息，弱识别会让这些示例在需要时缺席，而辨识度主要依赖这组对照示例。所以本版保留整组示例在可缓存的系统消息中。

## 说话方式：性格描述代替规则

“说话像真人发消息”一段改写成性格描述。实验结果：用性格描述代替“不用每句都反问”这条规则后，以问句结尾的回复从 27/60 降到 17/60，辨识度不变。

## 日记加入她自己的经历

每日日记的素材里增加 `your_experiences`：当天的喂食、睡醒、剧情和对局结果，都带时间。说明中要求只依据这些记录写自己的感受，不补写记录之外的经历。相处理解仍只依据用户原话。

## 验证

- `CharacterStateTest`（JVM）：
  - 睡醒的三个阶段。
  - 已回应过的标注。
  - 意图的产生、邀请、放下、结束和过期。
  - 场景暂停。
  - 重复提醒检测。
  - 不同本地日期的处理。
- `ScenarioEval` 加 `tests/scenarios/character-state.json`：用真实模型逐轮模拟多轮对话。事件按应用的方式记录，提示词由产品的 `PromptBuilder` 生成。每个关键回合写明“不该出现什么”或“应该做到什么”，由另一次温度为0的调用逐条判定。场景包括：
  - 刚醒与醒了一会儿。
  - 第一次被夸与连续被夸。
  - 输棋后闲聊再转入正事。
  - 邀请被拒后收住。
  - 劝睡之后不再重复。
  - 喂食之后不一直道谢。

  运行方法（`run-core` 会一起编译它，但不会自动运行）：

  ```bash
  DAFEIYU_API_KEY=sk-... java -Duser.timezone=Asia/Shanghai -cp build/core-tests:build/compile-check/classes:<org.json jar>:<android-all jar> com.xiaoxiao.pet.ScenarioEval assets/personas.json tests/scenarios/character-state.json build/scenario-report.json 2
  ```

  最后一个参数是每种风格重复的次数。
- 每次改动前后都跑一遍场景测试。报告和回复原文只留在本地，不提交。
