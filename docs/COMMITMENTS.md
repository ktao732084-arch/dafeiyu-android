# 双方约定：原话记录与 Dream 补漏

这个模块记录“谁答应过什么”，复用 `AgentStore` 的 JSON 文件、展示回执及每日整理。它不是新的人格层，也不新建定时任务、通知服务或任务执行器。

实现分支已同步主分支 `3153026`（包含人格分支 `a883ec3`）。日记、相处理解、口头禅学习和承诺补漏共用一次请求，各自仍有来源核验和独立存储；没有用旧版整理逻辑覆盖口头禅学习。

## 保存与补漏

1. 正常聊天提交时，从用户原话保守识别明确承诺，立即保存。无需聊天模型额外返回承诺字段。
2. 她的承诺只从实际展示的回复提取。分段显示时，只收已展示完整句；未展示、失败或取消的回复不作为承诺。查看已归档回复的全文也会走展示回执。旧版没有可靠展示依据的助手回复不用于 Dream 承诺补记。
3. 同一次每日 Dream/日记请求增加可选 `commitments`，最多四项。模型只提交 `source_id`、`speaker`（user/assistant）和逐字 `quote`；应用核对来源、说话者、原句及记忆开关记录。合法 JSON 返回后，慢环还会用保守的未来语句规则复查双方原话，补上模型漏掉的人或字段；每方最多新增两条，合计最多四条。已保存、被删除或无效的候选不占新增名额。不会拿她的日记或自由感受当作承诺证据。
4. 单条有明确未来约定的对话也可成为 Dream 材料；已展示的主动回复可以单独提供她的承诺素材，不伪造用户发言。即使没有保存日记正文，合法承诺也可单独保存。

本地规则优先收“我答应”“我会帮你”“十分钟后我提醒你”等明确语句；Dream 可补充“这份资料我周末给你”这样的其他表述。它仍有保守门槛，不保证覆盖任意省略句、跨轮只答“好”、隐喻或模糊表达。建议、能力说明、疑问、假设举例、引用、第三方承诺以及已完成的事情不作为新的约定。真实的有条件承诺保留完整前提；Dream 摘出半句时回到同一来源的完整句子核验，不能把假设或转述里的肯定部分单独入账。

2026-10-30 扩大测试后的修正：分类时区分书名/项目名、行动前的犹豫和行动后的祝愿，不再按全句是否包含“希望”“可能”一律丢弃；补充短句和明早/明晚等表达，同时收紧第三方、否定和未闭合引用。单句上限 480 字，包含可识别承诺的 Dream 摘录采用该上限，普通摘录及总输入预算保持原值。过长或含截断省略号的内容不作为完整承诺证据；保存仍为原话，不做模型改写。

不增加聊天前或逐轮的模型调用。Dream 继续使用每天最多一次的请求、最近三个已结束日期和既有输入预算；输出上限从 950 提高到 1300 tokens。即时保存只要求开启记忆；Dream 补漏同时要求开启记忆和陪伴日记。记忆关闭时说的话不会以后又被补记；关闭期间展示的助手回复也有单独的排除标记。

## 数据和状态

`commitments` 每条保存编号、speaker、逐字 quote、来源轮次、原话时间/时区、状态和 local/dream 来源。用户话按消息时间，她的话按原回复时间；查看旧回复不改写承诺的原日期。同一来源、同一说话者的重复或包含式摘录不重复保存。她的承诺不会进入用户事实或稳定自我设定。

- `open`：待确认，不代表一定没做到。
- `done`：用户在手账标记完成。
- `cancelled`：用户在手账标记取消。

完成、取消和恢复待确认由用户在手账操作。当前不让模型自动推断兑现，也不靠“过了十分钟”自动标记完成。实际对话中的新说明优先于未确认状态，但自动关闭/改期不在这版实现范围内。

给模型的约定资料补充中文状态含义：待确认不等于没做；手动完成不是实际收件凭证；已取消不再安排或催促。本轮取消/停止说明优先于旧账本和角色玩笑。这是上下文约束，不能保证任意模型必然遵守，也没有实现从自然语言自动永久关闭账本；长期状态仍由手账维护。

最多保留 200 条。满额时先移除已关闭记录并阻止从该来源重新补回；如果全是待确认，不静默淘汰它们，停止增加并在手账提示整理。模型每次最多看到六条，按本轮相关性、明确询问约定或主动考虑来选取，并分成“用户答应你的”“你答应用户的”两组，减少原话里“我”的歧义；不会全量注入。关闭记忆或专门回顾历史时不带这份当前约定背景。

“当时说的明天是哪一天”这类追问也会检索约定；原话含“明天”时按记录原时区提供对应日期。没有可核对条目的约定追问会得到缺乏依据的提示，防止空结果被误当成可以随口确认；关闭记忆时只给这个通用边界，不注入已存内容。人格正文、示例、口头禅与心情逻辑均未改动，PromptBuilder 只替换约定背景的一处调用。

“十分钟后我提醒你喝水”会作为她说过的话保留，而不是被当成已经设置或执行的提醒。现有主动陪伴仍受开关、忙碌状态、显示条件及模型选择的考虑时间控制；记录承诺不保证精确计时或后台主动送达。

## 手账和删除

记忆手账只增加一个“双方约定”入口，区分“你答应的”和“她答应的”。支持搜索、分页、看原话时间、标记状态、删除及清空。现有手账导出自动包含这些状态。

单条删除保留原聊天和既有事实记忆，但停止从同一说话者的该段原话自动补写。新轮次重新作出的承诺仍可保存。清空约定记录清空时间，防止用旧对话重建。若希望忘掉原话，应删除相应来源记忆/对话，而不只是删除约定条目。

删除来源对话时，相应双方承诺一起删除。清空聊天也清空约定；单独清空日记不清空约定。删除、清空和状态更新会递增 epoch；存储保留最新约定状态，旧的记忆引擎快照不能覆盖后台补记、展示进度或用户操作。删除会清除备份，迟到 Dream 不能恢复记录。

## 验证

- `CommitmentsTest`：双方归属、无记忆字段时的本地保存、未展示边界、长历史和重启、Dream 补漏、否定/假设/引用、来源校验、关闭记忆、删除/清空和旧快照隔离。
- `CommitmentsUiTest`：真实 Runtime 接线、只补承诺不写日记、手账标记及删除流程。
- `ExperienceInstrumentation`：独立 Android 包实际展示双方约定，核验先显示再记录、截图与标记完成。
- `CommitmentsLiveEval`：可选真实模型检查，两个风格分别跑六个提取场景和两句归属/执行核对，共 16 次请求；原始输出和 Key 不进入仓库。

初始结果和边界见 [双方约定验证](test-reports/commitments.json)。这批数据只能说明所测样例的归属和补漏情况，不代表任意语言表达都不会漏记或产生模型臆测，也不证明提醒已执行。

2026-10-30 应用户要求扩大至五种人格、46 个模板、500 次被测请求，另做 216 次评分请求。核心提取整例正确 210/270，挑战样例 0/30，存在稳定的误记/漏记及检索、状态表达问题。完整设计、全部 200 条聊天复核与下一步定位见 [扩大测试报告](COMMITMENTS_EXPANDED_EVAL.md)。本轮冻结产品，未合并或发布，不能再用初始 16 次检查代表整体可靠性。
