# 称呼与聊天同步

0.4.7起，称呼只有一个编辑入口：**名字与称呼 → 她怎么称呼你**。“陪伴设置”不再重复放置输入框。

## 使用方式

- 直接说“以后叫我kk”“请叫我小K”或“我叫kk，以后就叫我kk吧”。本轮成功保存后，设置会同步；不需要模型额外调用或用户再去填写。
- 在“名字与称呼”手动修改，会用于接下来的对话。手动清空后保持为空，不会再次从旧记忆补回。
- 升级后，如果称呼设置为空，会从仍有效的明确称呼记忆中补入一次。已有的非空设置会保留。2026-10-29实测中的kk记忆可走这条迁移路径。
- 关闭自动记忆不妨碍明确的称呼设置请求，但不会因此恢复自动提炼其他记忆。聊天失败、取消或被旧版本状态拒绝时，不更新称呼。
- 称呼属于个人设置，清空聊天或忘记记忆不会自动清空这个设置；需要清除称呼时在唯一入口删除内容并保存。

## 识别范围

使用本机保守规则识别明确的独立称呼指令，不让模型直接写设置。当前支持中文指令和长度不超过30个字符的中英文、数字等常见称呼；保留大小写。不会因为模型自称、别人姓名、历史回顾、假设、引述、问句或“叫我起床”这类动作请求改称呼。复杂、带引号或不明确的表达可能不自动处理，可改用简单指令或手动填写。

当前设置优先于旧聊天里的称呼；本轮明确更改的要求在本轮提示中即生效，但只有本轮保存成功后才落到设置。初始化人格不因称呼改变而改变。

## 实现与一致性

`Nickname`统一读写`agent.nickname`。`agent.nickname.migrated`防止一次迁移反复覆盖，`agent.nickname.origin`记录来源类别（manual、chat、memory-migration、none）。迁移先读取有效记忆，再加锁复查迁移标记，因此慢读取不能覆盖刚完成的手动编辑。

`AgentRuntime`在对话事务成功提交后应用明确称呼；模型只接收准备使用的称呼，不决定设置写入。手动保存先取消正在进行的请求；失败、取消、迟到回复不能覆盖最新设置。设置与聊天文件分别持久化，不宣称它们构成跨文件崩溃原子事务。

## 回复展示

新回复在解析时清理开头的`[tool]`、`[assistant]`通道标记；正文内部或引号/代码中的标签保留。提示词同时要求模型不要输出通道标签。旧记录仅在显示与上下文引用时隐藏这些前导标记，原始存档不重写，时间戳和分段回执保留。

未展示完整的回复仍可点开全文。气泡文本按自身宽度与行数测量，不再被下面较短的“部分已展示”按钮挤窄而截字。关闭聊天页后重绘首页的最新预览。

## 验证入口

- `ChatPolishRulesTest`：明确指令、排除情况、角色标记与原文保留。
- `ChatPolishTest`：唯一设置入口、取消/失败、迁移与手动编辑竞态、关闭自动记忆、真实字体布局、首页刷新。
- `tests/run-core-device.ps1`和独立Android instrumentation：使用产品DEX/类在Android ART上验证。

最新验证结果见根目录`VALIDATION.md`。真实聊天截图只保存在本地交付目录，不上传用户对话到公开仓库。
