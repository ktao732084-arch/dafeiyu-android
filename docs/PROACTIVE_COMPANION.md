# 主动陪伴与近期互动（0.4.9.1）

主动陪伴由手机端runtime安排。模型使用初始化时固定的人格、当前情绪、相关长期记忆、近期已展示对话、相关往事和触摸事件，自行决定开口内容或保持安静；不会再次随机人格。不增加电脑服务或额外决策模型。

## 记录如何使用

- 已成功提交的完整聊天继续保留原文、稳定ID、发送/回复/展示时间戳与时区，超出近期窗口时进入本机历史文件；未展示回复不能当作已经说过。
- 从0.4.8起，点击、拖动、抛掷、显示桌宠与长按菜单等接入现有touch路径，保存最近200条`interactions`：`at`（epoch毫秒）、`timeZone`、`kind`、`note`。这些不是永久完整的行为日志，也不补造升级前事件；被动息屏/唤醒背景不冒充用户触摸。
- 普通聊天与主动请求可看到最近12次物理互动，含当地可读时间。聊天背景还含最近6轮摘要、上次决定、当前等待状态、已提出未回应主题及连续主动但未收到文字回复的数量；相关往事仍从完整聊天本地检索。关闭记住重要的事时不注入长期记忆/往事，近期聊天与触摸背景仍可用。
- 每次主动考虑保存决定`quiet`、`speak`、`error`或`not-visible`与下一时间，`initiativeChecks`最多100条。安静、错误和未显示决定不作为她说过的话写入聊天。
- “记忆手账 → 最近互动”展示物理事件、上次决定与下次考虑时间。普通聊天可更新下一次时间而不改上次主动决定，所以两者不必属于同一请求。

## 节奏与开关

每次正常模型回复和主动决定返回整数`next_check_minutes`，范围2–180分钟。普通文本、缺失、字符串、小数、非有限值及越界数值均不会当作有效模型时间。启用主动陪伴时，至多在同一轮额外请求模型补齐一次，只采用控制字段，不替换原回复、记忆或人格；仍失败则持久标记`proactiveAwaitingPlan`并暂停主动消息，下一次正常聊天拿到有效计划后恢复。主动未开启、明确忙碌无需定时以及本机历史/记忆操作不额外补问。该时间是再考虑的时机，不是必须发消息或精确提醒的承诺。

模型还可返回`availability`（busy/available/unchanged）、`availability_evidence`（本轮用户逐字依据）、`initiative`（speak/quiet）与`topic`（稳定主题）。常见的明确第一人称忙闲句有本机意图保障，排除问句、假设、历史或转述；其他表达由模型依据当前原话判断。主动事件不能自行改变用户忙闲。

明确说忙会持久标记`proactiveWaiting`，移除下次时间，等用户明确说忙完/回来可聊再解除。普通闲聊不会自动解除；点击拖动也不会解除。用户随时可以明确告诉她现在可以聊天。这是在执行用户的等待意愿，不是每日次数或固定忙碌时长。

`initiativePlan`记录来源、合法分钟数、忙闲及其依据、是否补齐、主题、时间与轮次ID；成功聊天也保存本轮计划元数据。来源包含model/model_repair/missing，等待界面说明按用户忙碌意愿执行，不把缺字段伪称为模型选了15分钟。不保存原始网络包或Key。当前安排与上一次主动决定可能来自不同轮次。

主动回复中宣布“不催/不打扰/没人理我”等催促内容转为真实安静，不写聊天、不出气泡。主动话题和普通回复里带问号的主题仅在实际展示后记入未回应主题列表（最多8项），同主题再次主动输出转安静；下一轮用户发言清空该列表。模型仍可自行换自然话题，没有每日固定次数。主题标签及语义仍依赖模型，不能保证识别所有换词重复。

删除旧的聊天后30分钟、主动尝试间隔90分钟和每天最多3次的硬限制。保留两次尝试至少2分钟的防循环间隔、最近聊天/触摸后30秒缓冲。正常可主动时，新物理互动可把更远的计划提前到约2分钟后，交由模型重新判断；连续触摸不会造成并发请求。没有任何持久互动或聊天时不自动启动空白话题。

主动陪伴总开关默认关闭，已有用户选择不变；“夜间安静（23:00–08:00）”为默认关闭的独立开关。仍遵守用户暂停、系统勿扰、桌宠服务运行、亮屏解锁、桌宠可见且未收边、主界面/聊天页未打开，以及当前没有聊天请求。网络返回后再次检查，隐藏时不把回复假装已说出。

亮屏时每30秒做一次本地资格检查，并非每30秒请求模型。只有计划到期且可开口时调用现有聊天模型，正常一次请求完成“说不说、说什么、下次何时考虑”，缺有效时间时最多额外补问一次；即使决定安静，这次模型调用也会消耗API额度。频率没有每日固定上限，实际消耗随模型选择和互动变化。

网络失败按10、20、40、80、160分钟退避，成功或新的普通聊天重置。15分钟仅继续用作请求中的恢复租约，以及无新元数据的旧状态初次兼容计划，不作为新回复缺字段后的模型决定。请求开始保存15分钟保留期，避免请求中进程重启导致立即反复调用。计划落盘；App被强制停止后仍需重新开启服务，不能保证后台、息屏或厂商清理后准时触发。

## 数据一致性

聊天提交时合并最新互动和计划字段，避免记忆分析的旧快照覆盖它们。epoch隔离清空后的迟到结果与排队触摸。清空聊天同时清空近期互动、主动决定、等待状态、未回应主题和计划；不删除独立称呼设置。原有长期记忆是否保留取决于用户选择的清空操作。

实现为本项目新增的`Initiative.java`、`InitiativePlan.java`与已有runtime/store/prompt/UI接线，没有引入新外部运行框架。测试边界与已知限制见[验证记录](../VALIDATION.md)。
