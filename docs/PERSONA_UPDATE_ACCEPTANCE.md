# 拟人更新回归 · 2026-10-30

测试基线：main的`a2c2a54`，包含PR #25「连着发几句一起回、学会用户说法」和PR #26「五种性格的章节台词」。本轮发现并修复问题，未改版本、未发布安装包、未覆盖正式App。

## 复现与修复

1. 回复失败时，原代码用已发送消息覆盖输入框，丢掉用户正在打的补充。新增失败回归在原代码上失败，修复后按原顺序恢复已发送内容和未发送输入。
2. 回复刚保存、补话被暂存时，完成回调覆盖了后来继续输入的第三句。新增回归在原代码上失败，修复后同时保留暂存补话和当前输入；已保存回复仍正常展示。
3. 多条长消息合起来可能超过单条8000字限制，恢复草稿时调整可恢复长度，避免截断；重新发送后恢复普通输入限制。
4. 口头禅校验只检查候选短语，导致从带密码提示的合成原句中摘出的普通词仍被接受。新增核心检查在原代码上失败。现在来源原句也要通过已有敏感规则，同时过滤重复笑声/语气字；独特的短表达仍可学习。此规则不等于通用的隐私实体识别。
5. 新版GrowthTest读取`assets/personas.json`，设备脚本此前只传到根目录；已补齐资产路径，使五种剧情口吻检查实际在Android上执行。

## 模型效果与隔离边界

本轮用受控模型验证请求、取消、展示和存储机制；没有独立配置的真实模型评测凭据，也没有读取正式App保存的Key，所以未重新跑自然度或风格辨识盲测。Claude在PR里报告的真实模型成绩是其先前实验，不计入本轮复测。

静态审阅和产品渲染确认五种章节口吻不同，原句对应和占位符正确；这不能推导出真实模型每次都能自然借用口头禅，或长聊时始终不模板化。

使用独立包`com.dafeiyu.octoberpersonachecks`及合成聊天，测试结束仅卸载本轮包。首次尝试的通用测试包名与已有实例签名冲突，该次结果不计本轮；已使用独有包完整重跑。仅覆盖Android15模拟器，不代表实体手机矩阵。
