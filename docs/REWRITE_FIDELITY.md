# 润色保真

`RewriteGuard` 对含明确原句的常见润色/改写请求做独立校对。初始文本仍由原有聊天链路生成，保护在 `AgentReply.parse` 后、主动计划补齐和持久化之前执行。

## 边界

- 识别直接润色指令，原文来自一段完整外层引号或冒号后的文本；分离明确的“只输出正文”等末尾格式要求。
- 普通闲聊不增加请求。翻译、多个歧义来源、缺失原文，以及明确要求改时间/内容等请求不冻结旧原文。
- 不修改人格、例句或口头禅。润色材料不作为她自己的稳定设定保存。

## 执行

1. 原文与初稿完全相同直接通过。其他候选使用同一个已配置模型独立核对，资料通过JSON提供，不附人格和闲聊历史。
2. 明确否定/限制片段、数字和日期采用保守的本地原样检查。即使校对模型误判为通过，关键片段被改动仍返回原文。
3. 校对不通过时允许一次修正。修正版必须同时满足本地检查和第二次独立核对，否则返回完整原文，不继续循环。
4. 网络失败、缺字段、非法结果、无法确认均保留原文；取消例外，继续抛出取消信号，不能转成一次迟到保存。
5. 校对完成前不向监听器发送候选正文；保存与展示的都是最终文本。原有 epoch 校验继续阻止删除后的迟到提交。

DeepSeek 非推理模型的校对请求设置温度0，其余模型沿用其现有参数规则。通常多一次请求，修正时最多两次；原样回退可能牺牲润色幅度，但不靠机械替换词语制造一段新句子。模型语义核验仍可能漏判，本地锁定也不能穷举所有事实；不声称形式化证明所有改写等价。

## 验证

`RewriteGuardTest` 覆盖原文提取、显式改意、普通聊天跳过、错误通过、本地否定/数量/时间锁定、修正后再核验、失败回退和取消。`AgentInstrumentation` 在 Android 的真实 Handler、存储和 Runtime 上覆盖展示/保存顺序、取消、校对异常和删除竞态。真实模型原文及截图只留本地，不提交仓库。
