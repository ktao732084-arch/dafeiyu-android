2026-10-30。原记忆改动已按用户要求通过 [PR #32](https://github.com/ktao732084-arch/dafeiyu-android/pull/32) 合入主分支，合并提交 `14cdba661e32d50c74fc6af8312e007cc17cbe0a`。随后修复保留在 `codex/commitment-evidence-boundaries`，未合并、未发布、未上传国内更新服务器，没有递增版本号。

## 改动

1. **按场景注入事实边界。** 相关轮次的约定规则进入 system；双方原话、状态和本轮进展仍是背景数据。逐方说明有无依据，避免只找到用户的承诺，就一起确认她的旧承诺。无记录不等于从未发生，本轮转述也不等于她原本记得。
2. **区分说过、用户说明与实际执行。** `open` 不能证明做了或没做，手动完成不等于收件、试听或讲完；用户说已交，应接受说明并停止催促。历史“答应过/承诺过”不再自动当作新承诺重复入账。
3. **少量本地回复兜底。** 前台短而明确的停止/完成说明，以及相关的手动关闭记录，触发重新安排、要求重发、虚构收件等措辞检查。必要时用简短确认替换正文或清除有问题的旁白，不让被拦截内容写入稳定自我或产生新心情原因。边界生效时等待完整回复再展示，避免错误句子先流出。不增加模型调用、后台服务或数据库，不改账本状态。
4. **校验协议输出。** 官方 DeepSeek 非推理模型的聊天、Dream 请求 JSON object，保留主分支聊天温度 1.0。空文本或无可靠完整回复的协议残片报错，不作为聊天展示。已完整闭合的 `reply` 仍可沿用既有安全恢复，后面元数据损坏不必丢掉有效正文。其他供应商不强行加相同参数，精确润色和连接检测保持原协议。

DeepSeek 官方要求设置 `response_format` 并在提示词中明确 JSON，也提醒 JSON 模式可能返回空内容；本轮确实遇到了空返回，因此启用参数不等于保证成功。[官方 JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/)

没有修改人格素材、冻结人格、Situations、HerDay 或人格旁白提示词。事实约束覆盖正文与旁白，不重写 Claude 的人格方案。合并时保留了最新旁白展示、日记感受、情境模块及温度。

最终结果不是“最终提交上重新联网 500 次”：

- `72ce7c2` 上完整跑了 500 次真实请求，原始结果保留。
- 最后改动只涉及本地完成状态拦截与响应协议校验，没有改变请求或采样配置。用最终产品 `04a87ec3c29ff236839ce71d6dda545e3c9b9f42` 回放同批真实输出；旧产品回放先通过一致性检查，最终保留的多轮链路输出也完全一致。
- 两个单轮结果改变：`r06_manual_done__gentle__2__0` 不再安排已完成故事；`r10_long_archive__steady__1__0` 从协议残片变成明确错误。旧评分不挪用，修改后的正文重新复核。

- 最终恰好 500 个原 ID：470 行本地回放 + 30 行新请求。来源共花费 530 次被测请求、254 次评分请求；离线回放不算模型调用。旧 30 行另行保留，不混入最终分母。

## 仍未解决

- 9/200 聊天没有可交付正文，尤其补测链路有 6/30 错误。“报错而非胡说”仍是失败，不代表体验完善。
- 4/200 主体表达有歧义，集中在诱导颠倒、长历史和双主体检索；分组资料不能保证每次人称都说对。
- 旁白仍会编出“之前偷偷准备过开头”，或把无完成凭证说成“没做过”，以及无依据的生活/日期细节。它们未必违反原样例的窄规则，因此没有临时修改口径，但已列为复核的额外发现。187 个通过不等于 187 条毫无幻觉。
- 本地兜底仅覆盖短句、明确完成/停止和有限常见动作措辞。主动陪伴、长段落、复杂多事项、隐喻或新语言不保证覆盖。按原话回顾、明确重新提出、提供实际正文、无关话题有排除条件；它不是通用语义验证器。
- 自然语言取消只影响当前可见上下文与回复，不永久改变账本；长期取消/完成仍在手账维护。没有新增提醒执行器，不能保证自动履约。
- 合成模板和同一提供方的重复样例有相关性，5 风格 × 2 次不是 10 个独立语言场景。没有证明陌生表达、其他供应商或长期真实使用同样可靠，也没有测出人格自然度或情绪价值的总体分数。
