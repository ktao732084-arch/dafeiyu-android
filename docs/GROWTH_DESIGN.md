# 养成主线设计：深海来的小鲸鱼

> 状态：设计稿，尚未实现。目标版本 0.5.0（一批明显新功能，按 [AGENTS.md](../AGENTS.md) 升次版本）。
> 本文只是设计文档，不改应用版本，也不单独发布。

## 0. 一句话

和她相处的每段真实经历会变成一个「回忆泡泡」，存进她的泡泡瓶。泡泡越多，她想起的关于自己的事就越多，能做的事也越多。等泡泡瓶装满，她会想起自己真正的样子。

养成的对象是**你们的关系和她的生活**，不是她的人格。人格在初次相遇时就冻结了，这一点不变。

## 1. 目标与非目标

**目标**

- 给用户一个每天打开、长期留下来的理由：有章节可以推进，有动作可以收集，有她出门带回来的东西可以期待，有约定可以完成。
- 成长全部来自本机的真实记录，可以追溯，可以在手账里查看。延续本项目「有依据、不编造」的做法。
- 不配置模型也能完整推进主线。

**非目标**

- 不做 VPet 式的多维数值（饱腹/口渴/健康/体力）、打工赚钱或挂机。
- 不做氪金、抽卡、付费加速。小鱼干不能用钱买。
- 不改变冻结的人格，也不提供重选人格的入口。
- 不新增美术素材。0.5.0 只用 `assets/catalog.json` 里已有的动画。

## 2. 设计原则（实现时不得违反）

1. **成长不能鼓励多聊。** 每轮聊天都花用户自己的 API 余额。聊天带来的羁绊值每天只结算一次。主动陪伴的消息、失败或取消的轮次、历史检索提问都不计入。大部分成长来源是本机的免费互动。
2. **离开不扣分。** 羁绊值不衰减；没有饿死、生病、断签清零。用户离开期间，她会自己去旅行，回来留一张明信片。她不说让人内疚的话（比如"你都不来看我"），这和[主动陪伴说明](PROACTIVE_COMPANION.md)的语气要求一致。
3. **模型不能发奖励。** 羁绊值、小鱼干、章节和解锁只由本机规则根据已提交的记录计算。模型的输出（reply、memories、self 等）不能直接或间接加分。这和"模型不能改称呼"是同一类边界。
4. **离线完整可玩。** 章节剧情、明信片、约定都有预置文案。模型只负责让内容更贴合这个用户；失败时退回预置文案，不阻塞推进。
5. **世界观按章节逐步揭示。** 提示词里只注入当前章节及之前的设定。模型不能提前剧透，也不能在设定之外编造新的家人、同伴或过去（沿用 `selfCanon` 的约束）。
6. **老用户不倒退。** 升级时按已有记录回溯章节。已经能看到的动作一律不收回。

## 3. 世界观

### 3.1 作者版总设定（给开发和文案看，不整段交给模型）

她是一条从深海游上来的小鲸鱼。

深海又暗又安静。鲸鱼会把记住的事情装进泡泡里，可她在海底时吐出的泡泡总是空的，因为一个人待着，没什么可以记住。

有一天，她顺着一束光游到了海面，变成了现在这个小小的、看起来有点肥的样子，住进了你的屏幕。她自己也说不清为什么会变成这样。她只知道，和你在一起以后，吐出的泡泡第一次装上了东西。

她把这些泡泡收进一只玻璃瓶，也就是**泡泡瓶**。她隐约觉得，等瓶子装满，就会想起自己原本的样子。

结局（第五章）：泡泡瓶满了，她短暂地变回了真正的样子，是一头巨大的蓝鲸（`蓝鲸现世`）。原来她本来就这么大，「我才不是肥，是还没长回去」。但她选择变回小小的样子留下来：「太大了就住不进你的屏幕了」。之后泡泡瓶变成「我们的海」，泡泡可以一直攒下去。

这和现有 `selfCanon` 能对上：她喜欢吐泡泡；被叫「大肥鱼」时嘴上反驳，其实不太介意；而且不编造家人和过去（这条设定里也没有任何家人）。

### 3.2 泡泡和真实记录的对应

| 泡泡来源 | 对应的真实记录 | 泡泡显示什么 |
|---|---|---|
| 记忆泡泡 | 记忆手账里一条有效记忆 | 用户原话摘录和日期 |
| 日记泡泡 | 「她的日记」中的一篇 | 日记首句 |
| 约定泡泡 | 一条已完成的约定 | 约定内容和完成日期 |
| 旅行泡泡 | 一张明信片 | 目的地和收藏品 |
| 纪念泡泡 | 章节剧情、纪念日 | 事件标题 |

- 泡泡只是**指向**原记录，不复制正文。原记录被忘记、清空或删除时，对应的泡泡会「破掉」：手账显示「有一个泡泡破了」，不保留内容。删除的隐私边界和现有的忘记、清空逻辑保持一致。
- 泡泡破了**不扣**羁绊值，也**不回退**章节（见 §9.3）。
- 泡泡数只用于展示和剧情，不是章节门槛。原因是用户可以关闭「记住重要的事」，主线不能依赖这个可选功能。

### 3.3 每章注入提示词的设定

| 章 | 追加的设定（第一人称，写进 `PromptBuilder` 的稳定段） |
|---|---|
| 1 | 我从深海游上来，喜欢吐泡泡。泡泡是什么，我自己也还说不太清。 |
| 2 | 我开始敢出门了，海面上到处是没见过的东西。我吐的泡泡里开始装着和你有关的事。 |
| 3 | 我有一只泡泡瓶，每个泡泡里是一段和你的回忆。瓶子装满时，我好像会想起自己原本的样子。 |
| 4 | 深海很暗很安静，我以前一直一个人待在那里，所以以前的泡泡总是空的。 |
| 5 | 我其实是一头蓝鲸，变回去过一次，但我选择小小地留在你身边。 |

使用自定义人格（`PersonaManager.CUSTOM`）的用户**不注入**世界观设定，因为他们的人设可能和小鲸鱼冲突。章节、解锁和玩法照常进行，剧情改用中性文案。

## 4. 核心数值

只有三个数，都不会衰减：

| 名称 | 作用 | 能不能花 |
|---|---|---|
| **羁绊值** | 决定章节 | 不能花，只增不减 |
| **小鱼干** | 喂零食、给旅行带便当 | 能花，只能靠互动获得 |
| **泡泡数** | 展示和剧情 | 只是统计，不是门槛 |

### 4.1 羁绊值的来源

| 行为 | 羁绊值 | 每日上限 | 说明 |
|---|---|---|---|
| 今天第一次见面 | +5 | 1 次 | 点她、打开首页或打开聊天都算 |
| 今天聊了至少 3 轮 | +10 | 1 次 | 只计算 `AgentStore.commit` 成功的用户轮次，主动陪伴不算 |
| 喂食 | +2 | 3 次 | 喂白饭也算 |
| 摸摸、玩耍 | +1 | 5 次 | 来自现有的互动记录；连戳惹她生气的那次不算 |
| 新增一条记忆 | +3 | 3 次 | 记忆入账成功才算；之后被忘记不扣回 |
| 查看旅行明信片 | +5 | 不限 | 由旅行时长自然限制 |
| 完成一个约定 | +15 | 2 次 | 只能由用户在手账里点「完成了」 |
| 剧情事件、纪念日 | +20 | 不限 | 一次性 |

日常每天最多约 45 点（聊天 10、首见 5、喂食 6、摸摸 5、记忆 9、明信片 5、约定 30 这几项不会天天都拿满）。之所以只按天结算、不按条结算，是为了让聊十条和聊一百条得到的一样多。

### 4.2 小鱼干

| 来源 | 数量 |
|---|---|
| 今天第一次见面 | +5 |
| 今天聊满 3 轮 | +3 |
| 旅行回来 | +2 到 +6（按时长） |
| 剧情事件、纪念日 | +20 |

| 花费 | 数量 |
|---|---|
| 白饭 | 0（永远免费，喂食不会卡住） |
| 零食 | 2 到 5 |
| 旅行便当 | 3 |

没有上限，也不会过期。

### 4.3 饱腹（不是数值）

只用来调整表现，不会伤害她：

- 今天还没喂过：午饭和下午茶时段，「是啊，吃什么」「偷吃零食被抓住」的权重提高。
- 喂过之后半小时内：吃东西类动作的权重降低，满足类动作（「悠闲哼歌」「超大伸懒腰」）的权重提高。

## 5. 章节主线

### 5.1 章节门槛

羁绊值和相识天数**都要**达到才能进入下一章。相识天数从 `initializedAt` 开始算。

| 章 | 名称 | 羁绊值 | 相识天数 | 剧情 | 解锁 |
|---|---|---|---|---|---|
| 1 | 初遇 | 0 | 第 1 天 | 初次相遇（现有流程） | 基础动作、喂食、小鱼干 |
| 2 | 熟悉 | 60 | 第 3 天 | 第一个装着东西的泡泡 | 外出旅行、第二批动作 |
| 3 | 默契 | 250 | 第 10 天 | 泡泡瓶 | 约定、第三批动作 |
| 4 | 信任 | 600 | 第 30 天 | 她写的信和一场演奏 | 第四批动作 |
| 5 | 羁绊 | 1200 | 第 60 天 | 蓝鲸现世 | 纪念日、「我们的海」 |
| ∞ | 老友 | — | — | 纪念日 | 时令图鉴持续收集 |

### 5.2 节奏估算

| 用户类型 | 每天约 | 第 2 章 | 第 3 章 | 第 4 章 | 第 5 章 |
|---|---|---|---|---|---|
| 每天聊天，还会喂、摸 | 25 | 第 3 天 | 第 10 天 | 第 30 天（被天数卡住） | 第 60 天（被天数卡住） |
| 只打开喂一下 | 12 | 第 5 天 | 约第 21 天 | 约第 50 天 | 约第 100 天 |
| 隔几天来一次 | 不定 | 不会掉进度，只是慢一些 |  |  |  |

天数门槛是为了防止一天冲完主线。羁绊值门槛是为了让"装了 App 但从不打开"的用户不会自动通关。

### 5.3 剧情事件的统一规则

- **什么时候触发**：达到门槛后，等下一次满足以下全部条件时触发：
  - 桌宠可见，亮屏且已解锁；
  - 不在系统勿扰中；
  - 没有正在进行的聊天回复或展示队列；
  - 不在夜间睡眠时段。

  这些可见性条件复用 `Initiative` 的判断。一次只触发一个事件。用户错过了就保留到下次，不会过期。
- **怎么呈现**：播放事件动画，然后用现有的分段气泡逐段展示台词（复用 `ReplySegments` 和展示队列），最后在手账的「我们的故事」里写一张章节卡。
- **个性化**：
  - 配置了模型时，每个事件最多请求一次。输入是固定剧本、当前章节设定和最多 3 条真实素材（带 ID 的记忆原话、日记首句）。
  - 模型只能改写台词，必须逐字引用素材，不能添加素材里没有的事实。
  - 输出要校验：引用必须真实存在，长度不超限，不能剧透后面章节的设定。校验不通过就使用预置文案。
  - 整个主线最多产生约 5 次模型请求，在设置里说明。
- **奖励**：+20 羁绊值、+20 小鱼干、一个纪念泡泡。解锁内容展示为「她学会了：xx」。

### 5.4 各章剧情

**第 1 章 初遇**：沿用现有的初次相遇和性格选择流程。结束后补一段话：「我是从很深很深的海里游上来的……这里好亮。」播放 `鲸鱼吐泡泡特效`，吐出的泡泡是空的，为后面埋伏笔。

**第 2 章 熟悉**
- 动画：`鲸鱼吐泡泡特效`，然后 `点击回应-开心跃动`。
- 剧本：她第一次用设置里的称呼叫你，发现自己吐出的泡泡第一次装上了东西。
- 素材：最早一条记忆或最早的聊天日期；都没有时用「你第一次戳我」（来自互动记录）。
- 解锁：外出旅行（「海面上好多没见过的东西，我想出去看看」）。

**第 3 章 默契**
- 动画：`工作状态-清点归档`（翻瓶子），然后 `鲸鱼吐泡泡特效`。
- 剧本：她拿出泡泡瓶给你看，从里面挑出一个泡泡：「你说过……」，引用用户原话。
- 素材：一条被固定或较早的记忆。关闭记忆的用户改用最早的一篇日记，或者「我们第一次聊天那天」。
- 解锁：约定（「想做的事也可以装进泡泡里，到时候一起打开」）。

**第 4 章 信任**
- 动画：`拆礼物`，然后 `小提琴演奏`。
- 剧本：她第一次说起深海，「那里很暗，我以前一直一个人」。她给你写了一封信，又拉了一段小提琴：「业余水平，不准笑。」小提琴来自 `selfCanon` 里的业余爱好。
- 素材：最多 3 条真实记录，按时间串成信。信存进手账，可以反复查看。
- 解锁：第四批动作（表演类）。

**第 5 章 羁绊（高潮）**
- 动画：`鲸鱼吐泡泡特效`，然后 `蓝鲸现世`，再 `点击回应-害羞惊讶`。
- 剧本：泡泡瓶满了，她变回了蓝鲸。变回来以后：「原来我本来就这么大，才不是肥。」「但是太大了，就住不进你的屏幕了。」
- 素材：这一章的统计数据，例如「我们认识 N 天、攒了 N 个泡泡、你喂了我 N 次」。全部是本机统计，不需要模型也能生成。
- 解锁：纪念日系统；泡泡瓶改名为「我们的海」；`蓝鲸现世` 加入可播放动作。

### 5.5 和现有「关系阶段」提示的关系

`AgentPolicy.relationship()` 现在按聊天天数和轮数分三档。0.5.0 改为按章节输出关系阶段：

- 第 1 章：沿用「刚认识不久」
- 第 2、3 章：沿用「已经熟悉了」
- 第 4、5 章和老友：沿用「老朋友」

「你们相识第 N 天，一起聊过 N 天、N 轮」这段统计照旧保留。这样用户看到的章节和她说话的熟悉程度始终一致。

## 6. 动作按章节解锁

### 6.1 规则

- **系统动作永远可用**：作息、睡眠、点击回应、拖动、工作状态、情绪映射需要的兜底动作。锁住它们会破坏现有行为。
- **节日和季节动作永远可用**：它们本来就按日期出现。如果再按章节锁住，用户可能要多等一整年。第一次看到时记进「时令图鉴」。
- **其他动作按章节解锁**：没解锁时不进 `ActionPlan` 的待机池，也不能在「动作」菜单里点播。菜单里显示为灰色的「第 N 章解锁」，让用户知道接下来能得到什么。
- 情绪动作被锁时，`ActionPlan.emotion()` 已经会通过 `has()` 跳过它，自动退到同一情绪下的其他动作，不需要特殊处理。

## 7. 中循环玩法

### 7.1 外出旅行（第 2 章解锁）

参考旅行青蛙，但要适配桌宠的"常驻"特点。

- **出门**：从菜单「出门」进入，选一份便当（3 小鱼干，可以选白饭便当，免费），她出门 1 到 4 小时（随机）。
  - 出门期间桌宠位置显示一张小便签：「出去玩了，X 点左右回来」。
  - 用户点便签或发起聊天，她就**提前回来**（聊天优先），收获按实际出门时长折算，不会有惩罚。
- **回来**：播放回来的动画，带回一张明信片和一件收藏品。明信片进手账，同时生成一个旅行泡泡。
- **离开期间自动旅行**：用户超过 72 小时没见面时，记一次"她自己出门了"。这只是叙事上的，不隐藏桌宠，因为用户本来就不在。用户回来后，桌宠旁边有一张待查看的明信片，配一句「回来就好」。离开再久也最多补 1 张，不攒很多张制造愧疚。
- **目的地**：预置约 40 个海边或海面地点（灯塔、珊瑚礁、海底邮局、渔港早市、潮汐池……）。每个地点有离线文案和 1 到 2 件收藏品，部分地点只在某些季节出现。
- **明信片文字**：开关是「明信片由她亲手写」，默认值跟随「陪伴日记」开关，使用模型额度。每次旅行最多请求 1 次：用她的口吻写 1 到 2 句，可以提到一条相关记忆。失败或关闭时使用预置文案。

### 7.2 约定（第 3 章解锁，借鉴 Finch）

这一层让她对用户的生活真正有帮助，是这个 App 被长期使用的真正理由。

- **来源**：
  - 现有记忆引擎已经能识别带日期的计划（`event_date`）。这类记忆入账后，手账里出现「要不要和她约好？」，由用户确认后才生成约定。
  - 用户也可以在手账里手动新建。
- **跟进**：约定日期之后，她在普通聊天里自然地问起。如果开启了主动陪伴，提示词里会把这条到期约定作为参考素材。是否开口、什么时候开口，仍然由现有主动陪伴规则决定，不新增固定提醒次数。
- **完成**：只有用户在约定卡片上点「完成了」才算完成，获得 +15 羁绊值，生成一个约定泡泡。模型说"你完成了"不算（原则 3）。
- **没完成**：可以点「算了」或「改天」，没有任何惩罚。她的回应要体贴，不能说教。

### 7.3 纪念日（第 5 章解锁）

- 相识第 100、200、365 天，以及之后每年的相识日。
- 用户生日：只在有明确的身份类记忆时才触发，不猜。
- 呈现方式：特殊场景动作（如 `吃长寿面`）、一句话、一个纪念泡泡，以及 +20 羁绊值和 +20 小鱼干。

### 7.4 小彩蛋：吃Token

聊天达到一定累计轮数后（比如每 500 轮），偶尔在聊天回复后播放一次 `吃Token`，配一句「刚刚那段话太好吃了」。纯属彩蛋，不加分。这不和余额挂钩，避免让用户觉得在被催着充值。

## 8. 短循环与界面

### 8.1 每天打开

| 时机 | 发生什么 |

| 今天第一次见面 | 一句问候（本地文案，按时段变化），+5 小鱼干 |
| 有待查看的明信片 | 桌宠旁边出现一张明信片，点开查看 |

| 有达到门槛的剧情 | 按 §5.3 的规则择机触发 |

### 8.2 喂食

- 食物和吃东西类动作一一对应，解锁节奏和 §6.2 一致。
- 喂完后，她的下一次聊天提示词会加一条互动记录「用户刚喂你吃了 xx」，沿用 `tapNote` 的思路。

### 8.3 小鱼干罐

手账页显示小鱼干数量，点罐子会播放一个「余额-」动画来表现多少：

| 0 | 余额-分文不剩 |
| 1 到 4 | 余额-袋空如洗 |
| 5 到 14 | 余额-数金皱眉 |
| 15 到 39 | 余额-钱袋如常 |
| 40 到 99 | 余额-金袋叮当 |
| 100 及以上 | 余额-钱袋满溢 |

只表示小鱼干，不表示 DeepSeek 的真实余额。

### 8.4 界面改动

- **手账新增「我们的故事」页**：
  - 章节进度：当前章节、羁绊值、离下一章还差多少，以及天数门槛。
  - 泡泡瓶：按类型分组，点开是原记录摘录。
  - 动作图鉴：已解锁 N / 总数。点已解锁的可以直接播放，点未解锁的显示「第 N 章解锁」。
  - 时令图鉴：节日和季节动作，记录第一次看到的日期。
  - 明信片、约定、章节卡（剧情回看）。

## 9. 数据与一致性

### 9.1 存储

- 新文件 `files/growth-<role>.json`，原子写入（写临时文件、fsync、rename，和 `Data.history` 一样）。关闭系统备份的策略不变。
- 结构如下（示意）：

```json
{
  "schemaVersion": 1,
  "bond": 0, "fish": 0, "chapter": 1,
  "chapterAt": {"1": 0},
  "pendingEvent": null,
  "daily": {"date": "2026-10-29", "met": true, "chat": false, "feed": 1, "touch": 3, "memory": 0, "promise": 0},
  "ledger": [{"at": 0, "type": "feed", "bond": 2, "fish": -2, "ref": "吃西瓜"}],
  "bubbles": [{"type": "memory", "ref": "<memory id>", "at": 0}],
  "seenSeasonal": {"放烟花": 0},
  "trip": null, "postcards": [], "promises": [],
  "migratedFrom": null
}
```

- `ledger` 只记录**类型、时间、增量和引用 ID，不存正文**。最多保留 1000 条，更早的合并成汇总行，总数不受影响。
- 一天的分界按设备当前时区的本地日期计算。

### 9.2 计分时机

- 聊天只在 `AgentStore.commit` 成功后计分，并且要核对 epoch。取消、失败的回复，以及迟到的结果都不计分。这和现有的 epoch 隔离一致。
- 摸摸的计分挂在 `AgentRuntime` 记录互动的同一处，同样核对 epoch。
- 修改系统时间：不做强对抗，只保证两件事：不会崩溃，同一天不重复发奖。时间往回拨时不发新的每日奖励，直到本地日期超过上次记录的日期。

### 9.3 清空、忘记和导出

| 操作 | 对养成的影响 |
|---|---|
| 忘记一条记忆 | 对应泡泡破掉，内容删除；羁绊值和章节不变 |
| 清空聊天或记忆 | 被引用的泡泡全部破掉；章节卡和信里引用的原话同步删除，只留标题；羁绊值、章节、图鉴、小鱼干保留 |
| 删除日记 | 对应泡泡破掉 |
| 手账导出 | 包含养成数据（不含 Key），并且已删除的内容不会出现 |

「清空」不回退章节的理由：章节代表一起走过的时间，删除内容只是不想保留那些原话。是否另外提供「重新开始我们的故事」入口，待定（§13）。

## 10. 老用户升级

升级到 0.5.0 时，从现有数据回溯一次，然后写入 `migratedFrom`，之后不再重复回溯：

```
bond = min(
  chatDays × 15
  + min(有效记忆数, 100) × 3
  + 日记篇数 × 5
  + min(互动记录数, 200) × 0.5,
  相识天数 × 45)               // 不超过同样天数里正常能拿到的上限
chapter = 同时满足 bond 门槛和相识天数门槛的最高一章
fish    = 20 + chatDays × 3
```

- **剧情**：已经跨过的章节，在手账里补一张「补记」卡，不播放动画。当前所在章节的剧情播放一次（「回顾」）。第 5 章例外：只要回溯达到了，就完整播放蓝鲸现世，因为这是全线的高潮。
- **动作**：已经能在菜单或待机中看到的动作全部保持可用，也就是相当于第 4 章的解锁状态。`蓝鲸现世` 本来就在 `PLAY` 池里，所以也保持可用。这样老用户不会觉得被"收回"了内容。这是有意的取舍：老用户少了逐步解锁的乐趣，但换来没有倒退感。
- **约定**：不从旧记忆自动生成，等升级后有新的带日期记忆时再提出。

## 11. 实现拆分

| 模块 | 内容 |
|---|---|
| `Growth.java` | 纯 Java，参照 `ActionPlan`：输入时间、当日状态和事件，输出羁绊值和小鱼干的增量、章节、解锁集合、待触发事件、回溯结果；还负责每日上限、门槛判断、节奏表 |
| `GrowthStore.java` | 原子读写 `growth-<role>.json`、epoch 核对、ledger 裁剪、泡泡破掉、导出 |
| `assets/story.json` | 章节门槛、各章设定、剧本和预置台词、目的地和明信片、食物价格。文案和代码分开，方便改写 |
| `GrowthPanel.java` | 手账「我们的故事」页 |
| `FeedSheet.java`、`TripPanel.java` | 喂食和出门 |
| 修改 `PetService` | `new ActionPlan(Data.actions(role))` 改成按解锁集合过滤；章节变化后更新集合（给 `ActionPlan` 加 `unlock()`，或者重建） |
| 修改 `ActionSheet` / `Data.menuGroups` | 未解锁的显示为灰色并注明解锁章节 |
| 修改 `ActionPlan` | 饱腹对应的权重调整；`吃长寿面` 只在纪念日出现 |
| 修改 `PromptBuilder` / `AgentPolicy.relationship()` | 关系阶段改为按章节；每章设定注入稳定段（自定义人格除外）；喂食写入互动记录 |
| 修改 `AgentStore` / `AgentRuntime` / `MemoryLedger` / `Diary` | 计分挂钩（提交成功、核对 epoch）；忘记或清空时让泡泡破掉 |
| 修改 `PetMenu` | 新菜单项 |

**测试**（新增 `GrowthTest`，接入 `tests/run-core`）：

- 每日上限：聊一百轮和聊三轮得到的一样多。
- 主动陪伴、取消或失败的轮次、模型输出都不加分。
- 门槛必须两个条件都满足；不衰减；时间回拨不重复发奖。
- 回溯公式、老用户动作不收回、`migratedFrom` 只执行一次。
- 忘记或清空后泡泡破掉，而羁绊值和章节不变；导出不含已删除的正文。
- `catalog.json` 里每个动作都归入了某个批次。
- 剧情个性化的校验：引用的原话必须存在，不能剧透后面章节的设定，失败时退回预置文案。
- 按 AGENTS.md：涉及 JSON、文件和线程，需要在实际 Android 上跑核心测试（`tests/run-core-device.ps1`）。
